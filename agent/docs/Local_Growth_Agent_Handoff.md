## 7. 建议下一步开发优先级

如果继续开发 Local Growth Agent，建议按下面顺序。

### P0：先做数据和规则

1. 固定数据字段模板；
2. 写 Excel/CSV 导入；
3. 做字段识别和标准化；
4. 做指标计算；
5. 做数据质量检查；

### P1：再做日报

1. 生成账户健康摘要；
2. 生成计划诊断表；
3. 生成素材诊断表；
4. 生成策略排序；
5. 输出 Markdown 日报。

### P2：再做反馈闭环

1. 记录采纳/误报/观察；
2. 记录误报原因；
3. 形成案例库；
4. 建立黄金测试集。

### P3：最后做 Dashboard

Dashboard 不建议作为第一阶段重点。先把日报跑稳定，再做可视化。

## 9. 后续接手者注意事项

### 9.1 不要重新发明规则

已有规则分散在：

- `douyin-local-push-analysis/references/analysis-framework.md`
- `douyin-local-push-analysis/references/douyin-local-push-rules.md`
- `douyin-local-push-analysis/references/paid-ads-enhancement-playbook.md`
- `Local_Growth_Agent_MVP开发方案.md`

开发前应先读取这些文件。

### 9.2 不要让 AI 编造数据

系统必须遵守：

- 只能用输入表里的数据；
- 缺字段就说缺字段；
- 无法判断就明确说无法判断；
- 每条建议必须有数据依据。

### 9.3 不要一开始做自动化投放

V1 是 Decision Support，不是自动执行。

禁止 V1 做：

- 自动改预算；
- 自动暂停计划；
- 自动发布素材；
- 自动回复客户；
- 自动操作广告平台。

### 9.4 报表口径要统一

当前不同文件有轻微口径差异：

- 单元报表留资 15；
- 素材报表留资 15；
- 截图口径平台留资 16；
- 截图口径有效留资 10。

后续系统必须在日报中标注数据来源和口径差异。

### 9.5 销售反馈是关键

本地推不能只看后台 CPL。后续必须尽量补齐：

- 有效留资；
- 电话接通；
- 微信通过；
- 无效原因；
- 首响时间；
- 预约/成交。

没有这些数据时，系统只能判断前端投放，不能判断真实获客质量。

## 11. 当前最重要的业务原则

```text
不要按“留资量”加预算。
要按“有效留资成本 + 能触达 + 微信通过率”加预算。
```

投放动作原则：

```text
先停亏钱的，
再降变差的，
保留历史好的，
小加新跑出来的，
重做已验证方向。
```
