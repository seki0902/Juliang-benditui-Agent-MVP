# 每日运行修复与运行看板

更新：2026-09-18。实际生产目录为 `Juliang-benditui-Agent-MVP/agent`，其他 V1 目录是既有副本，此次未同步改动。

## 使用

打开 http://127.0.0.1:8898 ，或双击项目中的 `打开运行看板.cmd`。页面每 5 秒刷新，按次显示执行步骤、开始与结束时间、错误、日报及外部同步回执。支持状态筛选和阅读日报；顶部的「立即运行 Agent」按钮可以在电脑晚于 09:00 开机时手动启动同一条日报流程。页面没有广告执行或自动审批入口。

本地服务只绑定 127.0.0.1，不上传数据，不需要 Codex 持续运行。Windows 登录时由 `Local Growth Agent Dashboard` 启动；必要时执行 `scripts/start_dashboard.ps1`。前端源码在 `dashboard/dist`，服务入口为 `src/dashboard_server.py`。

## 故障证据和修复

- 系统任务实际存在；旧沙箱无法枚举任务，不能据此推断未注册。任务上次在 09:13:27 启动，退出码为 1。
- 09-16 和 09-17 的首次运行均在 `Download.save_as` 遇到 `TargetClosedError`；本次复现确认页面已关闭。切换后台模式和仅做重试仍失败。
- 改为从专用持久化 Profile 读取登录存储到内存，随后关闭它，在新的临时浏览器会话中下载；不将登录存储写入日志或文件。修复后的独立下载以及随后完整日报各自一次成功。
- 这证明隔离会话方案在本机通过验证；没有足够原生崩溃证据判定 Chrome 内部的具体缺陷。不能将推测写成已确认的浏览器版本问题。
- 下载阶段最多尝试 3 次，只对浏览器关闭/瞬时网络下载故障重试。登录失效不会自动绕过验证。
- 每日主入口加入操作系统文件锁，防止定时与手动任务并发占用浏览器。
- 读取本次下载清单中的确切文件，而非静默改用最新历史文件；对账失败停止同步。
- 每次尝试独立写入 `outputs/run_history`，补跑保留此前失败记录，进程退出但未记录结尾显示“已中断”。
- 日报、石墨、消息回执分别展示。外部步骤失败或关闭时整体显示“部分完成”。数据库 `success` 仍表示核心报告已持久化，`metadata.pipeline_status` 保存完整流程结果，以避免补跑重复发送。
- `run_manifest.json` 只有在流程结束才写最终状态。只有推送服务的成功回执，不代表收件人已阅读。

## 调度

`Local Growth Agent Daily`：每天 09:00，当前交互用户，允许唤醒；错过后可补跑；失败后间隔 5 分钟最多重启 2 次；限制 30 分钟；忽略重复实例。下载内部重试与 Windows 重启分层执行。石墨和推送不会在下载内部重试中重复执行。

电脑仍需开机，Windows 用户须已登录。允许唤醒不等于能够从关机启动；浏览器登录过期仍需要人工登录。Codex 无需常开。电脑晚于 09:00 开机时，打开看板后点击「立即运行 Agent」即可补跑；系统任务“上次退出码”仍可能显示此前自动任务的结果，因为按钮触发属于手动运行。

## 维护

调度配置修改后执行 `scripts/register_daily_task.ps1`；看板自启动配置执行 `scripts/register_dashboard_task.ps1`。两者需要实际 Windows 用户环境而非沙箱中的任务枚举视图。

看板服务仅允许固定 API 与日报文件白名单，不提供任意文件读取、写操作或跨域访问。推送错误中的令牌 URL 会脱敏。请勿把 `runtime/chrome-profile`、凭据文件或 state 数据库公开发布。
