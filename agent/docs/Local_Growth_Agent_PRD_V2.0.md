# Local Growth Agent
## 本地推运营分析 Agent PRD V2.0

---

## 一、产品定位

### 1.1 项目名称

**Local Growth Agent（本地推智能运营分析助手）**

### 1.2 一句话介绍

> 一个通过数据分析、业务规则和大模型推理协同工作的 AI 运营分析 Agent，每日自动诊断本地推投放效果，定位问题原因，并生成带数据依据的优化建议。

---

# 二、产品背景

## 2.1 当前业务痛点

本地推运营每天需要面对：

- 多账户、多计划、多素材数据
- 消耗、成本、转化等指标波动
- 素材疲劳判断
- 计划优化
- 销售承接质量判断

目前主要依靠人工完成：

1. 导出数据
2. 制作日报
3. 查看异常指标
4. 凭经验判断原因
5. 给出优化动作

### 主要问题

| 问题 | 影响 |
|---|---|
| 数据查看耗时 | 每天约 30–60 分钟 |
| 依赖个人经验 | 新人难以快速成长 |
| 问题发现滞后 | 异常可能持续数天 |
| 优化原因无法沉淀 | 经验无法复制 |

---

# 三、产品目标

## 3.1 V1目标

建立一个：

> **每天自动完成投放健康检查，并辅助运营决策的 AI 助手。**

## 3.2 成功指标

### 效率指标

- 日报生成时间 < 10 分钟
- 人工复盘时间降低 50% 以上

### 准确指标

- 核心异常识别准确率 > 85%
- AI 建议有效采纳率 > 60%

### 稳定性指标

- 每日生成日报成功率 > 95%
- 数据异常能够被识别并提示，不允许静默失败

# 六、Agent 体系

## 6.1 数据质量 Agent

### 目标

保证进入分析流程的数据可信。

### 输入

每日投放数据。

### 检查内容

- 数据是否完整
- 字段是否缺失
- 数据是否异常
- 是否存在数据断流
- 是否存在明显不合理的数据

### 输出示例

```text
数据状态：

✅ 账户数据完整

⚠️ 销售反馈数据缺失

影响：
当前无法判断线索有效率问题。
```

### 产品原则

如果关键数据缺失：

> Agent 必须明确告诉用户“无法判断什么”，而不是强行给出结论。

---

# 6.2 账户健康 Agent

### 目标

判断整体投放状态。

### 分析维度

#### 成本

- CPL 上涨
- 成本下降
- ROI 变化

#### 转化

- 线索下降
- 转化下降
- 转化率变化

#### 消耗

- 消耗异常增加
- 消耗突然下降
- 消耗停止

### 输出示例

```text
账户健康度：78分

主要风险：

1. 有效成本上涨 22%
2. 昨日线索下降 18%

建议：
进入计划层进一步分析。
```

---

# 6.3 计划诊断 Agent

### 目标

从账户层异常进一步定位到具体问题计划。

### 分析内容

- 消耗贡献
- 成本变化
- 转化变化
- 计划状态
- 历史趋势

### 输出示例

```text
问题计划：

计划A

数据：

过去3天消耗上涨 35%
线索增长仅 5%

判断：

放量效率下降。

建议：

降低预算 20%–30%，并观察后续成本变化。
```

---

# 6.4 素材分析 Agent

### 目标

判断素材生命周期和素材表现异常。

### 关注指标

- CTR 趋势
- CVR 趋势
- 消耗趋势
- 素材历史表现

### 素材状态

#### 新素材

数据不足：

> 进入观察期，不直接判断好坏。

#### 成长素材

可能表现为：

- CTR 提升
- 成本下降
- 转化增加

#### 疲劳素材

例如：

- CTR 连续下降
- 同时消耗持续增加

### 输出示例

```text
素材状态：

疲劳风险

原因：

近3日 CTR 持续下降，
但消耗未同步下降。

建议：

测试新素材进行替换。
```

---

# 6.5 销售质量 Agent

### 定位

**可选插件。**

### 目标

分析投放产生的线索进入销售环节后的真实质量。

### 输入

销售反馈数据。

### 分析内容

- 有效线索率
- 首响时间
- 销售承接情况
- 后续转化情况

### 关键约束

如果没有销售数据：

> **不得推测销售质量。**

必须输出：

```text
当前缺少销售反馈数据，
暂无法判断销售承接质量问题。
```

---

# 6.6 策略 Agent

### 定位

**整个系统的核心 Agent。**

前面的 Agent 负责：

> 发现问题、定位问题。

策略 Agent 负责：

> **把多个问题转化为今天应该做什么。**

### 需要解决的问题

不同 Agent 的建议可能发生冲突。

例如：

- 素材 Agent：素材表现下降，建议替换
- 计划 Agent：该计划仍然有较高转化，建议继续投放

策略 Agent 不能简单地把两个建议拼在一起。

它需要综合：

- 问题严重程度
- 消耗规模
- 成本影响
- 转化贡献
- 历史趋势
- 预算约束
- 数据完整程度

最终形成优先级。

### 输出格式

| 优先级 | 动作 | 原因 |
|---|---|---|
| P0 | 降低计划A预算 | 成本异常上涨且消耗占比较高 |
| P1 | 替换素材B | CTR连续下降，存在疲劳风险 |
| P2 | 观察计划C | 当前数据不足以形成明确结论 |

### 策略原则

Agent 不应该只给出一个绝对答案。

当数据存在冲突时，应明确告诉用户：

> 当前数据不足以判断，需要人工确认。

# 七、业务规则库

## 7.1 定位

业务规则库是 Agent 的“运营 SOP”。

它负责告诉系统：

> 什么叫异常？什么情况下需要进一步分析？

---

## 7.2 异常规则

示例：

| 指标 | 条件 | 等级 |
|---|---|---|
| CPL | 上涨 20% | P1 |
| 消耗 | 超过预算 90% | P0 |
| CTR | 连续下降 3 天 | P1 |
| 线索 | 大幅下降 | P1 |

具体阈值由业务方根据真实历史数据确定。

---

## 7.3 诊断规则

示例：

```text
成本上涨
    ↓
检查消耗是否增加
    ↓
检查 CTR 是否下降
    ↓
检查 CVR 是否下降
    ↓
定位主要异常维度
```

---

## 7.4 历史案例库

保存历史真实案例：

- 当时的数据
- 当时出现的异常
- 优化师判断
- 实际采取的动作
- 最终结果

用途：

> Agent 遇到类似问题时，可以参考过去的真实案例。

---

# 八、AI 可靠性设计

## 8.1 数据约束

AI：

- 只能使用输入数据
- 不允许编造数字
- 不允许编造计划名称
- 不允许编造历史数据
- 不允许把推测描述成事实

---

## 8.2 不确定性表达

必须允许 Agent 输出：

> “无法判断”。

例如：

### 错误

> 销售质量下降导致成本上涨。

### 正确

> 当前缺少销售反馈数据，无法判断销售质量是否是成本上涨的原因。

---

## 8.3 证据链

每条诊断和建议必须附带数据依据。

示例：

```text
问题：

计划A成本上涨。

数据依据：

昨日 CPL：100元
今日 CPL：130元
涨幅：30%

进一步观察：

CTR下降 18%
CVR基本稳定

判断：

当前更可能与点击效率下降有关。
```

# 十四、Prompt约束

Agent必须遵守以下基本原则。

## 原则1：事实优先

只能根据输入数据进行判断。

---

## 原则2：禁止幻觉

禁止：

- 编造数字
- 编造数据
- 编造计划
- 编造原因

---

## 原则3：禁止越权

Agent只负责：

> 分析与建议。

不直接执行：

- 修改预算
- 暂停计划
- 删除素材

---

## 原则4：明确不确定性

如果数据不足：

> 必须明确说明无法判断的原因。

---

## 原则5：建议必须有依据

任何优化建议都必须能够追溯到：

> 数据 → 异常 → 判断 → 建议

# 十八、产品核心原则

## 原则一：先确定，再智能

能用确定规则判断的问题：

> 不交给大模型自由发挥。

---

## 原则二：AI负责推理，不负责编造

LLM的价值：

> 解释、归因、综合、决策辅助。

而不是：

> 自己创造事实。

---

## 原则三：每一个结论都要有证据

运营看到建议后，应该能够回答：

> “你为什么这么判断？”

---

## 原则四：允许Agent说不知道

一个可靠的 Agent：

> 不是任何问题都给答案，而是知道什么时候不能判断。

---

## 原则五：人工反馈必须进入产品

用户的：

- 采纳
- 误报
- 忽略
- 修正

都是系统未来优化的重要数据。

---

# 十九、最终产品定义

> **Local Growth Agent 是一个面向本地推运营的 AI 决策辅助系统。**
>
> 它通过标准化数据输入、业务规则、异常检测和大模型推理，完成从“发现问题”到“定位原因”再到“给出优化建议”的完整诊断链路，并通过运营反馈和历史案例持续优化。
>
> 它不直接操作广告平台，而是帮助运营更快、更准确地完成每日复盘和决策。

## V2.0核心价值

**不是：**

> “AI帮我写一份日报。”

而是：

> **“AI每天替我完成第一轮运营复盘，并告诉我哪里出了问题、为什么，以及今天最值得做什么；如果它判断错了，我还能纠正它。”**
