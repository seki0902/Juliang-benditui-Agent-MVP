# 投放执行控制

## 当前实现（2026-09-15）

入口 `src/execute_action.py`；控制器 `src/execution_controller.py`；页面适配器 `src/browser_executor.py`。

1. `prepare --candidate <单条候选JSON> --target <金额或paused>`：只读实时页面，校验策略，保存具体原值/目标值，返回动作ID与SHA256指纹。待确认有效期30分钟。
2. 展示完整动作给用户，收到用户明确确认后才能调用 `approve --id <ID> --digest <完整指纹> --confirmation "确认执行 <ID> <完整指纹>"`。后台任务不得自行生成确认；石墨普通反馈不作为审批。
3. `execute --id <ID>`：只能执行已批准且未过期的动作。重新读取实时值，任何变化均停止；同一动作只能领取一次。
4. 执行后刷新核对预算/状态及计划身份，保存前后截图。审计在 `state/execution.sqlite3`；截图在 `output/playwright/execution`。
5. 提交超时、执行中断或复核失败为 `unknown` / `executing`，需要人工核查，绝不自动重复提交或自动回滚。再次改动需新的具体确认。

预算支持单次增加或减少不超过10%；单日异常禁止增加和暂停。暂停使用逐日完整数据校验，缺失值不当作0。开启计划、修改出价、素材和删除均不在执行范围。

`browser_execution_config.json` 中真实页面定位尚未校准，保持 `calibrated=false`，适配器会明确阻止启动。没有把猜测选择器当作可用定位。本轮按用户要求未运行测试、回放或真实投放操作。

预算与项目开关位于“项目”页，而现有日报导入以“单元 ID”为粒度。候选只有在正式日报提供单元到项目的可追溯映射 `execution_project_targets` 后才能生成；计划名称相同或人工观察到的 ID 不得作为映射依据。

此控制层依照账户负责人 2026-09-15 的授权：

- 单次预算调整最多 10%；
- 连续 3 天有消耗、平台留资为 0 的计划可形成暂停候选；
- 单日异常只能形成降预算候选，不能形成暂停候选；
- 所有投放改动都必须先获得人工确认；本版执行器仅实现预算和暂停。

每日任务只生成 `pending_execution_actions.json` 和日报中的“待确认投放动作”，不会点击任何本地推修改控件。

真正执行时，浏览器执行器必须依序完成：

1. 按计划 ID 和名称定位唯一计划；任一条件不唯一即停止。
2. 读取当前后台状态与当前日预算，和待确认动作再次核对。
3. 向负责人展示动作 ID、计划、当前值、目标值和证据，等待明确确认。
4. 预算变更只能在当前值的 ±10% 内；单日异常不允许暂停。
5. 提交后重新读取页面确认状态/预算已生效，并写审计记录。
6. 登录失效、验证码、页面选择器变更、数值异常或任何核对失败，立即停止且不改动投放。
