# Local Growth Agent MVP 开发方案

更新时间：2026-08-10

## 1. MVP 目标

Local Growth Agent 的 MVP 目标不是做一个复杂 SaaS，而是先做出一个能稳定帮助运营完成每日复盘的本地工具。

MVP 一句话目标：

```text
导入本地推报表和销售反馈数据后，系统能在 10 分钟内完成数据检查、账户/计划/素材诊断，并输出一份有证据链的 Markdown 日报。
```

MVP 不做自动投放操作，只做决策辅助。

## 2. MVP 范围

### 2.1 V1 必须做

| 模块 | 是否做 | 说明 |
| --- | --- | --- |
| Excel/CSV 导入 | 做 | 支持账户/计划/素材/销售反馈数据 |
| 数据质量检查 | 做 | 检查字段缺失、空表、异常值、口径不一致 |
| 指标计算 | 做 | CTR、CVR、CPL、CPM、有效率、有效成本 |
| 账户健康分析 | 做 | 判断整体消耗、成本、转化、有效线索趋势 |
| 计划诊断 | 做 | 找出问题计划和可保留计划 |
| 素材分析 | 做 | 判断素材加预算、保留、降预算、关停 |
| 销售质量分析 | 做，但可选 | 有销售数据才分析，没有就明确说明无法判断 |
| 策略建议 | 做 | 输出今天应该做什么，按 P0/P1/P2 排序 |
| Markdown 日报 | 做 | 每天生成一份可复制、可沉淀的日报 |
| 反馈记录 | 做轻量版 | 记录建议是否采纳、误报、需要观察 |

### 2.2 V1 暂不做

| 功能 | 暂不做原因 |
| --- | --- |
| 自动修改预算 | 风险高，MVP 只做建议 |
| 自动暂停计划 | 风险高，需要人工确认 |
| 自动发布素材 | 涉及审核、素材管理、平台权限 |
| 广告平台 API 自动取数 | 先用 Excel/CSV 验证分析逻辑 |
| 复杂 Dashboard | 先用 Markdown 日报验证价值 |
| 多用户权限 | 当前是个人/小团队运营工具 |
| 云端 SaaS | 先做本地 MVP |

## 3. MVP 产品流程

```text
用户导入数据
    ↓
系统识别数据类型
    ↓
数据质量检查
    ↓
指标标准化计算
    ↓
账户健康分析
    ↓
计划诊断
    ↓
素材分析
    ↓
销售质量分析（如有）
    ↓
策略 Agent 综合排序
    ↓
生成 Markdown 日报
    ↓
用户反馈：采纳 / 误报 / 观察
    ↓
沉淀到案例库
```

## 5. 指标计算

所有衍生指标必须由系统计算，不建议直接依赖表格里的口径。

| 指标 | 公式 | 用途 |
| --- | --- | --- |
| CTR | clicks / impressions | 判断素材吸引力 |
| CVR | leads / clicks | 判断点击到留资效率 |
| CPL | spend / leads | 判断前端留资成本 |
| CPM | spend / impressions * 1000 | 判断流量价格 |
| 有效率 | valid_leads / leads | 判断线索质量 |
| 有效留资成本 | spend / valid_leads | 判断真实获客成本 |
| 私信留资转化率 | leads / private_messages | 判断私信承接效率 |
| 电话接通率 | phone_connected / leads | 判断销售触达 |
| 微信通过率 | wechat_added / leads | 判断私域承接 |
| ROI | revenue / spend | 有成交数据时判断最终效果 |

异常处理规则：

- 分母为 0 时，不输出 `#DIV/0!`，输出 `-` 或 `无法计算`。
- 数据缺失时，不推测，只说明缺少字段。
- 2026-08-10 这类半日数据必须标注“非完整日”。

## 6. 健康度评分 V1

健康度总分 100 分。

| 模块 | 权重 | 说明 |
| --- | ---: | --- |
| 数据质量 | 20 | 字段完整、数据无异常、口径一致 |
| 成本健康 | 25 | CPL、有效 CPL 是否异常上涨 |
| 转化健康 | 25 | 留资量、CVR、有效率是否稳定 |
| 素材健康 | 20 | CTR、素材疲劳、0 留资素材比例 |
| 销售承接 | 10 | 电话接通、微信通过、首响时间 |

如果没有销售反馈数据：

```text
销售承接模块不强行打分，日报中标记“销售数据缺失，无法判断后端质量”。
```

### 6.1 数据质量扣分

| 情况 | 扣分 |
| --- | ---: |
| 缺少日期 | -10 |
| 缺少消耗 | -10 |
| 缺少展示/点击 | -5 |
| 缺少留资 | -10 |
| 销售反馈缺失 | 不扣总分，但标记无法判断 |
| 出现负数、异常大值 | -5 至 -20 |

### 6.2 成本健康扣分

| 情况 | 扣分 |
| --- | ---: |
| CPL 较近 3 日均值上涨 20%-30% | -5 |
| CPL 较近 3 日均值上涨 30%-50% | -10 |
| CPL 较近 3 日均值上涨 50% 以上 | -15 |
| 有效留资成本高于账户均值 50% 以上 | -15 |

### 6.3 转化健康扣分

| 情况 | 扣分 |
| --- | ---: |
| 留资量下降 20%-30% | -5 |
| 留资量下降 30%-50% | -10 |
| 留资量下降 50% 以上 | -15 |
| 有效率低于 60% | -5 |
| 有效率低于 40% | -15 |

### 6.4 素材健康扣分

| 情况 | 扣分 |
| --- | ---: |
| CTR 连续 2 天下降 | -5 |
| CTR 连续 3 天下降 | -10 |
| 单素材消耗超过目标有效 CPL 1.5 倍且 0 有效留资 | -10 |
| 单素材消耗超过目标有效 CPL 2 倍且 0 有效留资 | -15 |
| 0 留资素材消耗占比过高 | -5 至 -15 |

### 6.5 销售承接扣分

| 情况 | 扣分 |
| --- | ---: |
| 电话接通率低于 60% | -5 |
| 微信通过率低于 40% | -5 |
| 首响时间超过 2 小时 | -5 |
| 大量电话无法触达 | -10 |

## 7. 异常等级规则

### 7.1 P0：今天必须处理

| 条件 | 示例动作 |
| --- | --- |
| 消耗达到目标有效 CPL 2 倍，仍 0 有效留资 | 停素材/计划 |
| CTR 低于 0.5%，且持续消耗 | 暂停素材 |
| 计划消耗异常飙升 | 立即检查预算/出价/小数点 |
| 定向包或排除包疑似选反 | 立即人工复核 |
| 素材存在明显合规风险 | 立即下架/替换 |

### 7.2 P1：重点关注并调整

| 条件 | 示例动作 |
| --- | --- |
| CPL 较 3 日均值上涨 30% 以上 | 控预算 20%-30% |
| 有效留资成本高于账户均值 50% 以上 | 降预算或换素材 |
| CTR 连续 2-3 天下降 | 上新替换素材 |
| 有留资但有效率低于 40%-60% | 改筛选和表单 |
| 新计划预算占比超过 30% | 控制测新预算 |

### 7.3 P2：继续观察

| 条件 | 示例动作 |
| --- | --- |
| 新素材未满 2-3 天 | Hold |
| 单日 CPL 波动但 3 日均值正常 | Hold |
| CTR 低但有效线索质量好 | 小预算保留 |
| 样本量过低 | 继续观察 |

## 8. Agent 模块设计

### 8.1 数据质量 Agent

职责：

- 识别数据类型；
- 检查必填字段；
- 检查空值、负数、异常值；
- 判断是否有销售反馈数据；
- 输出“可以判断什么 / 不能判断什么”。

输出示例：

```text
数据质量：可用

已识别：
- 计划日维度数据
- 素材日维度数据
- 销售反馈数据

缺失：
- 预算字段
- 出价字段

影响：
- 可以判断前端成本和素材表现
- 暂无法判断预算利用率和出价是否合理
```

### 8.2 账户健康 Agent

职责：

- 计算账户总消耗、留资、CPL、CTR、CVR、有效成本；
- 对比昨日、近 3 日、近 7 日；
- 输出账户健康分；
- 标记主要风险。

输出格式：

```text
账户健康度：78分

主要风险：
1. 有效留资成本较近3日均值上涨 35%
2. CTR 连续 2 天下滑
3. 销售反馈中电话无法触达占比偏高
```

### 8.3 计划诊断 Agent

职责：

- 按计划拆消耗、留资、有效留资；
- 找出高消耗低转化计划；
- 判断计划是 Scale / Hold / Control risk / Stop。

输出格式：

| 计划 | 问题 | 数据依据 | 判断 | 建议 |
| --- | --- | --- | --- | --- |
| 计划A | 成本上涨 | CPL 200 → 320 | 放量效率下降 | 降预算 20%-30% |

### 8.4 素材分析 Agent

职责：

- 判断素材生命周期：新素材、成长素材、稳定素材、疲劳素材、无效素材；
- 分析 CTR、CVR、CPL、有效线索；
- 输出素材级动作。

素材状态规则：

| 状态 | 定义 | 动作 |
| --- | --- | --- |
| 新素材 | 未满 2-3 天或样本小 | 观察 |
| 成长素材 | CTR/CVR 提升，成本下降 | 小幅加预算 |
| 稳定素材 | 成本和有效率稳定 | 保持 |
| 疲劳素材 | CTR 连续下降，成本上升 | 做改版/降预算 |
| 无效素材 | 消耗高、0 有效留资 | 停 |

### 8.5 销售质量 Agent

职责：

- 分析有效率；
- 电话接通率；
- 微信通过率；
- 首响时间；
- 无效原因分布。

关键规则：

```text
没有销售反馈数据时，不得推测销售质量。
必须输出：当前缺少销售反馈数据，无法判断销售承接质量。
```

### 8.6 策略 Agent

职责：

- 综合前面 Agent 的发现；
- 解决建议冲突；
- 按 P0/P1/P2 排序；
- 输出“今天最应该做什么”。

冲突处理规则：

| 冲突 | 优先判断 |
| --- | --- |
| CPL 低但有效率低 | 不加预算，先改筛选 |
| CTR 高但无有效线索 | 不加预算，查表单/承接 |
| 历史好但近 2 天衰退 | 做改版，不硬加原素材 |
| 新素材单日好但样本小 | 保留观察，不大放量 |
| 计划仍有转化但素材疲劳 | 保计划，替换素材 |

```markdown
- 有点击但无留资，不是纯曝光问题，而是转化承诺/表单承接问题。

- 改成“找机构前问清3个问题”方向。

- 待观察。
```

## 12. 黄金测试集 V1

先做 10 个案例，后续扩到 20 个。

| 案例 | 输入特征 | 标准判断 | 标准动作 |
| --- | --- | --- | --- |
| Case 1 | 消耗 500，0 有效留资 | 高风险 | 停 |
| Case 2 | CPL 低，但有效率 30% | 低质线索 | 不加预算，改筛选 |
| Case 3 | CTR 连续 3 天下滑 | 素材疲劳 | 做改版 |
| Case 4 | 新素材单日 CPL 很低 | 样本不足 | 观察 |
| Case 5 | CTR 高，CVR 低 | 吸引低意向 | 改表单/承接 |
| Case 6 | 留资少但有效率高 | 量小质好 | 保留小预算 |
| Case 7 | 搜索计划成本高但有效率好 | 高意向流量 | 保留 |
| Case 8 | 后台提示调价但业务稳定 | 不盲从 | Hold |
| Case 9 | 预算突然耗尽 | 预算/时段问题 | 查预算和高峰 |
| Case 10 | 销售数据缺失 | 无法判断后端 | 明确提示缺失 |

验收目标：

```text
10 个案例至少判断对 8 个，进入下一阶段。
20 个案例至少判断对 18 个，达到 PRD 中黄金测试集目标。
```

## 14. 开发阶段拆解

### Phase 1：数据基础

目标：证明数据链路可用。

任务：

- 支持 Excel/CSV 导入；
- 识别账户/计划/素材/销售反馈数据；
- 标准化字段名；
- 计算基础指标；
- 输出处理后的 CSV。

验收：

- 能读取当前本地推单元报表和素材报表；
- 能正确计算 CTR、CVR、CPL、CPM；
- 遇到缺失字段能提示。

### Phase 2：规则诊断

目标：系统能发现明显问题。

任务：

- 实现 P0/P1/P2 异常规则；
- 实现 3 日均值对比；
- 实现素材状态判断；
- 实现账户健康评分。

验收：

- 能识别 0 留资高消耗素材；
- 能识别 CTR 连续下降；
- 能识别有效成本过高；
- 能输出异常列表。

### Phase 3：AI 日报

目标：系统能把数据和规则结果转成可读日报。

任务：

- 设计日报 prompt；
- 将指标、异常、建议传给 LLM；
- 强制 LLM 引用数据依据；
- 输出 Markdown 日报。

验收：

- 日报结构稳定；
- 每条建议都有数据依据；
- 缺失数据时会明确说明无法判断。

### Phase 4：策略 Agent

目标：从“发现问题”升级到“今天做什么”。

任务：

- 合并账户、计划、素材、销售建议；
- 处理冲突；
- 按 P0/P1/P2 排序；
- 输出动作、幅度、对象、复盘时间。

验收：

- 不会把所有建议简单堆叠；
- 能优先处理高消耗低转化问题；
- 能区分关停、降预算、保留、加预算、改素材。

### Phase 5：反馈闭环

目标：让 Agent 能持续变准。

任务：

- 增加反馈记录；
- 支持采纳/误报/观察；
- 记录误报原因；
- 生成案例库；
- 建立黄金测试集。

验收：

- 每条建议可记录反馈；
- 误报案例可复盘；
- 黄金测试集能评估 Agent 输出。

## 16. 第一版优先级清单

如果现在就开始做，建议按这个顺序：

| 优先级 | 任务 | 原因 |
| --- | --- | --- |
| P0 | 固定数据字段模板 | 没有数据标准，后面都不稳定 |
| P0 | 做指标计算 | 所有诊断都依赖指标 |
| P0 | 做数据质量检查 | 防止 AI 基于错误数据分析 |
| P0 | 做异常规则 | 先用确定规则判断明显问题 |
| P1 | 做 Markdown 日报 | 先输出可用结果 |
| P1 | 做策略排序 | 帮运营知道今天先做什么 |
| P2 | 做反馈记录 | 开始沉淀经验 |
| P2 | 做黄金测试集 | 后续验证准确率 |
| P3 | 做 Dashboard | 等日报稳定后再做 |

## 17. 最小可运行版本定义

最小可运行版本只需要做到：

```text
输入：
1. 单元/计划报表
2. 素材报表
3. 可选销售反馈表

处理：
1. 字段识别
2. 指标计算
3. 异常检测
4. 策略建议

输出：
1. 今日结论
2. 异常列表
3. 计划诊断
4. 素材诊断
5. 今日动作
6. 无法判断项
```

只要这个跑通，就已经能满足 MVP 的核心价值：

```text
每天替运营完成第一轮复盘，并告诉运营今天最值得做什么。
```
