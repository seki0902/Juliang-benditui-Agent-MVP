# 正式历史接入诊断

2026-09-15：已接入每日任务 `_finalize_success`，本轮仅实现和阅读代码，不运行测试、日报任务或9月回放。

## 数据流

当前下载与导入 → 按账户读取 SQLite 成功记录 → 在内存中合并 → 基线、月累计、状态、异常 → 日报 → 保存当日指标。

- 历史读取严格早于当前统计日，不扫描旧文件；读取不到时从当前正式数据开始积累。
- 读取按账户 ID 过滤；已有元数据明确对账失败的运行不参与历史比较。
- 当天指标和历史汇总分开，落库仍保存当天输入，防止把历史累计再次当成日消耗。
- 近3/7/30日均为自然日；对照窗口为近3日前的7日，不与当前窗口重叠。
- 比较需要当前3天都有对象记录，前7日窗口至少有3天记录，且满足既有曝光/点击门槛。
- 窗口成本由总消耗除以总数量计算；另保留日指标均值、中位数和范围。
- 缺失日期不补零，未出现的对象不推断为后台暂停；首次观察不推断为新建计划。
- 当前仅输出异常候选及 CHECK_DATA，不凭前端数据自动放量或关停。
- 月累计要求月初到统计日的账户数据齐全；有效留资或对接任一天缺失，对应累计不冒充完整值。
- 增强后的结构化输出为 `daily_report.json`，Markdown 增加历史覆盖与近期状态。
